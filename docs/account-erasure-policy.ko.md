# 회원탈퇴 데이터 파기 정책

이 문서는 `account-erasure-v1` 구현과 운영 기준을 설명합니다. 법률 자문을 대체하지 않으며, 실제 사업자 정보와 결제 도입 여부가 정해지면 개인정보 전문가의 검토를 받아야 합니다.

## 처리 원칙

- 회원탈퇴는 본인 재확인 후 즉시 확정하며 앱에서 복구 기능을 제공하지 않습니다.
- 이메일, 소셜 계정 연결, 인증 토큰과 사용자 소유의 민감·개인 데이터는 물리 삭제합니다.
- 다른 참여자의 기록 이해에 필요한 공동 모임 자체는 유지하되 작성자 이름, 기기 ID와 nullable 사용자 연결을 익명화합니다.
- 외래키 무결성이나 변경 이력 증명에 필요한 사용자 행은 이메일 없이 `탈퇴한 사용자`로 익명화한 tombstone으로 유지합니다.
- 파기 완료 감사 원장에는 사용자 ID, 이메일, 해시를 저장하지 않고 정책 버전, 처리 시각, 삭제·익명화 행 수만 저장합니다.

## 데이터별 처리

| 분류 | 처리 | 주요 데이터 |
|---|---|---|
| 인증·식별 | 물리 삭제 | 로그인 제공자 연결, refresh token, 비밀번호 재설정 token, 가입 이메일 인증 |
| AI | 물리 삭제 | 암호화 대화 문맥, 지난 질문·답변·기도문 기록, 사용량, 요청 영수증, 답변 피드백 |
| 개인 신앙 기록 | 물리 삭제 | 기도, 성경일기, 신앙 검사 답변·결과 |
| 성경 이용 기록 | 물리 삭제 | 메모, 스크랩, 하이라이트, 읽기 위치·이력 |
| 알림 | 물리 삭제 | FCM token, 알림 설정·발송·읽음 기록, 수신 이메일 outbox |
| QT 개인 콘텐츠 | 물리 삭제 | 질문 답변, 개인 묵상, 출석, 목장 멤버십 |
| QT 공동 모임 | 익명화 후 유지 | 참여자 표시 이름·기기 ID, 목장 리더, 모임 생성자 표시 이름 |
| 운영 콘텐츠 이력 | 익명 사용자 참조 또는 nullable 참조 제거 | 관리자 감사, AI 설정, 오늘의 말씀·해설 검수 이력 |
| 파기 감사 | 비식별 최소 보관 | 정책 버전, 요청·완료 시각, 처리 건수 |

## 트랜잭션과 장애 처리

- 사용자 행 익명화와 관계 데이터 삭제는 하나의 DB 트랜잭션에서 처리합니다.
- 존재하는 테이블의 SQL이 하나라도 실패하면 전체 처리를 롤백하고 성공 응답을 보내지 않습니다.
- DB 커밋 후 사용자별 Redis AI 캐시 인덱스를 최선 노력으로 삭제합니다. Redis 장애가 있으면 캐시는 설정된 TTL 이후 만료됩니다.
- 이 정책 배포 전에 생성되어 사용자별 인덱스에 연결되지 않은 AI 캐시는 기본 설정 기준 최대 24시간 안에 자연 만료됩니다.

## 백업과 법정 보존

- 운영 DB에서의 삭제와 시점 복구용 백업에서의 만료는 같은 시점이 아닐 수 있습니다.
- 백업은 접근 권한을 제한하고 정해진 회전 주기가 지나면 파기하며, 일반 서비스 조회나 분석에 재사용하지 않습니다.
- 결제, 세금, 분쟁 대응 자료가 추가되면 일반 사용자 테이블과 분리하고 법적 근거·보존기간·접근자를 별도로 관리해야 합니다.
- 현재 파기 감사 원장은 사용자와 다시 연결할 수 없는 통계성 운영 기록입니다.

## 남은 출시 과제

- Google, Apple, Kakao 소셜 전용 계정에 provider 최근 재인증 또는 단기 탈퇴 승인 token을 적용합니다.
- 운영 백업 보존기간과 복구 후 재삭제 절차를 개인정보처리방침에 명시합니다.
- 인앱결제 도입 시 회원탈퇴와 구독 취소가 별개임을 안내하고 스토어 서버 알림을 연동합니다.
- 사용자 규모가 커지면 삭제 처리 시간과 실패율을 관측하고, 동기 API 제한을 넘는 경우 durable 삭제 작업으로 전환합니다.
