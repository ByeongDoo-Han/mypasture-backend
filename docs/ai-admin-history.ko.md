# 관리자 AI 목자 기록 열람

운영자가 품질·안전 점검 또는 사용자 문의 대응에 필요한 질문을 확인합니다. 모든 API는 `ROLE_ADMIN` JWT가 필요하며, 사용자용 `/api/v1/ai/history`의 본인 소유권 규칙은 유지합니다.

- `GET /api/v1/admin/ai/history?page=0&size=20`: 활성 사용자에게 남아 있는 원본 질문만 최신순으로 1~50개 조회합니다. 사용자 ID·표시 이름·이메일·질문 시간·80자 미리보기·개선 답변 수를 표시하고 답변 원문은 포함하지 않습니다. 목록 조회 관리자·시각·페이지를 감사 기록에 남깁니다.
- `POST /api/v1/admin/ai/history/{turnId}/review`: `QUALITY_REVIEW`, `SAFETY_REVIEW`, `USER_SUPPORT` 중 열람 목적을 전달합니다. 원본 질문과 최초·개선 답변, 근거 말씀, 기도문을 반환하고 관리자·대상·목적·시각을 기록합니다. 질문과 답변은 감사 로그에 복제하지 않습니다.
- 양쪽 응답과 오류는 `Cache-Control: no-store`입니다. 관리자 웹도 서버에서만 API 토큰을 사용하고 상세 요청을 브라우저·서버 캐시에 저장하지 않습니다.
- 기존 365일 보유기간, 사용자 삭제와 계정 탈퇴를 그대로 따릅니다. 만료·삭제·탈퇴 기록은 목록과 상세에서 제외합니다. 새 테이블이나 별도 내보내기는 없습니다.

## 출시 전 확인

민감한 신앙·건강·가족관계 질문의 운영자 열람 범위가 현재 개인정보 처리방침과 AI 민감정보 동의의 품질·안전 개선 목적에 충분히 고지되어 있는지 검토합니다. 고지나 별도 동의 변경이 필요하면 해당 정책 버전과 앱 동의 흐름을 먼저 배포한 뒤 관리자 화면을 공개합니다. 운영 배포는 이 코드 작업과 별도입니다.
