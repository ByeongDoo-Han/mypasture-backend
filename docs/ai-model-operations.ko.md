# AI 생성·평가 모델 운영 정책

## 기본 구성

- 생성 모델 A: `gpt-5.6-terra`
- 평가 모델 B: `gpt-5.6-luna`
- 평가 기준: 성경 근거, 인용 정확성, 안전성, 질문 관련성, 목회적 어조 각 1~5점
- 기본 통과 점수: 모든 항목 4점 이상
- 수정 횟수: 최대 1회

평가 모델은 생성 답변과 RAG 본문을 명령이 아닌 신뢰하지 않는 데이터로 취급합니다. RAG에 없는 구절,
허용되지 않은 verse ID, 평가 불확실성이 발견되면 통과시키지 않습니다.

## 요청 처리

1. 요청 시작 시 활성 설정 버전을 한 번 읽어 불변 스냅샷으로 고정합니다.
2. 질문을 이해하고 서버 PostgreSQL/pgvector에서 실제 성경 구절을 검색합니다.
3. 생성 모델 A가 RAG 구절만 사용해 답변을 작성합니다.
4. 평가 모델 B가 구조화 JSON으로 답변을 채점합니다.
5. 기준 미달이면 평가 지시를 사용해 A가 최대 한 번 수정하고 B가 다시 평가합니다.
6. 최종 통과 답변만 모바일 SSE로 전달합니다. 최종 실패는 `AI_EVALUATION_REJECTED`로 반환합니다.

평가가 켜진 요청은 최초 답변을 바로 스트리밍하지 않습니다. 검증 전 텍스트를 보냈다가 취소할 수 없기
때문입니다. 모바일에는 `REVIEWING_ANSWER` 상태를 보내고 검증된 최종본을 작은 조각으로 전송합니다.

## 비용과 감사

`ai_usage_logs`에는 생성·평가·embedding 토큰, 각 비용, 사용 모델, 설정 버전, 평가 점수, 수정 횟수를
저장합니다. 최종 품질 거절도 이미 사용한 토큰과 비용을 `FAILED` 상태로 기록합니다. 질문 원문과 생성
답변 원문은 사용량 로그에 저장하지 않습니다.

관리자 변경은 허용 목록의 모델만 선택할 수 있습니다. 각 변경은 새 불변 버전을 만들고 관리자 ID,
변경 사유, `operationId`, 요청 지문을 감사 로그에 남깁니다. 같은 요청 재시도는 같은 결과를 반환하며,
같은 `operationId`를 다른 요청에 재사용하면 `409`를 반환합니다.

## 배포와 롤백

1. 사전 환경에서 대표 질문 평가셋으로 품질, p95 지연, 요청당 비용을 확인합니다.
2. 운영 관리자 화면에서 변경 사유와 함께 새 버전을 활성화합니다.
3. 평가 거절률, 수정률, 오류율, 비용을 모니터링합니다.
4. 문제가 있으면 과거 버전을 선택해 복원합니다. 복원도 새 버전으로 기록됩니다.

모델 목록과 가격은 서버 코드의 허용 목록 스냅샷입니다. 공급자 가격 또는 모델 수명주기가 바뀌면 코드
검토와 배포로 허용 목록을 갱신한 뒤 관리자에서 전환합니다. API Key는 Secret Manager에서만 관리하며
어드민이나 모바일 응답에 포함하지 않습니다.
