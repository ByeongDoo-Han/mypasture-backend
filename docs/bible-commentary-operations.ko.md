# 장별 성경 해설 생성·검수 운영 가이드

## 운영 원칙

- 장별 해설은 사용자 요청 시 생성하지 않고 사전에 생성·검수·게시합니다.
- 공개 API는 현재 성경 본문의 해시와 일치하는 최신 `PUBLISHED` revision만 반환합니다.
- 성경 원문은 서버 DB에서 조회하며 모델이 만든 성경 문장을 원문으로 저장하지 않습니다.
- 역사·문화·문학 배경은 관리자가 승인한 근거 메모만 생성 입력에 사용합니다.
- 외부 주석 원문은 사용권을 확보하지 않은 상태에서 복사해 저장하지 않습니다.
- 교단별 견해가 갈리는 내용은 복수 견해 또는 해석상 주의사항으로 표현합니다.

## 상태 흐름

```text
근거 메모: DRAFT -> APPROVED -> RETIRED

생성 작업: PENDING -> PROCESSING -> COMPLETED | FAILED

해설:
  자동 평가 통과 -> DRAFT -> PUBLISHED
  자동 평가 실패 -> REJECTED -> 관리자 수정 revision -> DRAFT -> PUBLISHED
  기존 게시본 + 새 게시본 -> 기존 게시본 SUPERSEDED
```

관리자가 초안을 수정하면 기존 row를 덮어쓰지 않고 새 revision을 만듭니다. 이전 revision은 `SUPERSEDED`로 보존되며 수정자와 수정 사유는 검수 이벤트에 기록됩니다.

## 생성과 자동 평가

1. 워커가 `FOR UPDATE SKIP LOCKED`로 한 작업만 점유합니다.
2. 성경 장 본문과 해당 권·장에 적용되는 승인 근거를 조회합니다.
3. `BIBLE_COMMENTARY` 활성 AI 설정의 생성 모델로 구조화 초안을 생성합니다.
4. 별도 평가 모델이 본문 충실성, 역사 근거, 교차 참조 관련성, 신학적 중립성, 가독성을 1~5점으로 평가합니다.
5. 기준 미달이면 평가 지적을 전달해 설정된 횟수만 재작성합니다.
6. 모든 생성·평가 시도의 토큰과 비용을 합산해 저장합니다.
7. 최종 평가 실패 후보도 `REJECTED`로 남겨 운영자가 문제를 분석할 수 있게 합니다.

존재하지 않는 교차 구절, 절 범위 누락·중복, 빈 항목은 저장 전에 프로그램 검증으로 차단합니다. 자동 평가를 통과해도 사람 검수와 검수 의견 없이는 게시할 수 없습니다.

## 책 단위 생성

책 단위 요청은 다음 장을 건너뜁니다.

- 이미 생성 대기 또는 처리 중인 장
- `includePublished=false`일 때 게시본이 있는 장
- 본문 상태가 `EMPTY` 또는 `SOURCE_MISSING`인 장

응답의 `queuedChapters`, `skippedChapters`, `unavailableChapters`를 확인해 부분 성공을 운영자가 판단합니다. 대량 생성 전에는 대표 장 30~50개를 먼저 검수해 장르별 프롬프트 품질을 확인합니다.

## 근거 메모 정책

- `sourceName`, HTTPS `sourceUrl`, `licenseNote`를 기록합니다.
- 책 전체 근거는 `chapter=null`, 특정 장 근거는 장 번호를 사용합니다.
- 승인 전 메모는 AI 입력에 포함되지 않습니다.
- 권리 만료, 오류 발견, 출처 신뢰도 하락 시 즉시 `RETIRED` 처리합니다.
- 한 요청에는 최대 8개 근거만 전달해 비용과 컨텍스트 오염을 제한합니다.

## 게시 전 체크리스트

- [ ] 모든 절이 구간 해설에 한 번씩 포함되는가
- [ ] 성경 교차 참조가 실제 본문과 문맥에 맞는가
- [ ] 역사적 설명이 승인 근거에서 확인되는가
- [ ] 모델이 성경 문장을 새로 만들어 원문처럼 표현하지 않았는가
- [ ] 논쟁적 해석을 단정하지 않았는가
- [ ] 묵상 질문이 죄책감이나 공포를 과도하게 유도하지 않는가
- [ ] 모바일에서 읽기 어려운 분량이나 표현이 없는가

## 운영 지표

- 장당 생성·평가 토큰과 비용
- 최초 평가 통과율과 재작성 통과율
- 자동 평가 실패 사유 분포
- 관리자 수정률과 평균 게시 소요 시간
- 사용자 오류 신고율
- 본문 변경으로 `sourceHash`가 불일치한 해설 수

## 실행 순서

요청 예시는 `http/bible-commentary-admin.http`에 있습니다. 운영에서는 먼저 승인 근거를 등록하고, 대표 장을 단일 생성한 뒤 품질을 확인합니다. 책 단위 생성과 전체 1,189장 생성은 별도 운영 승인 후 단계적으로 수행합니다.
