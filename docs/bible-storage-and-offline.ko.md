# 성경 저장 및 오프라인 설계

## 서버 저장 단위

성경 원문은 절 단위로 저장합니다.

```text
bible_books 1 ─ N bible_chapters 1 ─ N bible_verses
```

절의 논리 키는 `(version, book_id, chapter, verse)`이며 DB의 `bible_verses.id`를 사용자 기능의
참조 키로 사용합니다. 한 장 조회는 해당 장의 절 행을 번호순으로 한 번에 조회해 응답합니다.

절 단위 저장이 적합한 기능은 다음과 같습니다.

- 북마크, 하이라이트, 개인 메모와 스크랩
- AI RAG 근거 및 인용
- 단어 검색과 추천 말씀
- 여러 절을 조합하는 말씀 카드
- 절별 공유 및 딥링크

사용자 기능 테이블에는 성경 본문을 복사하지 않고 `verse_id`를 저장합니다. 원문 교정 import에서도
기존 절 ID를 유지해야 사용자 참조가 끊기지 않습니다.

## 장 상태

`bible_chapters.content_status`는 다음 의미를 가집니다.

| 상태 | 의미 |
| --- | --- |
| `AVAILABLE` | 원본 파일을 검증하고 절을 적재함 |
| `EMPTY` | 해당 장은 존재하지만 최초 원본 파일이 없어 절이 없음 |
| `SOURCE_MISSING` | 과거 적재한 절은 있으나 현재 원본 파일이 없어 기존 데이터를 보존함 |

현재 베드로전서 5장은 `EMPTY`로 저장하며 API는 `200 OK`, `contentStatus=EMPTY`, `verses=[]`를 반환합니다.
존재하지 않는 절을 임의로 만들거나 `verse=0`인 가짜 행을 저장하지 않습니다.

## 말씀 카드

편집 중인 말씀 카드는 선택한 `verse_id` 목록을 참조합니다. 사용자가 이미지로 내보내거나 게시한
카드는 나중의 오탈자 교정에도 결과가 바뀌지 않도록 아래 값을 스냅샷으로 함께 저장하는 것이 좋습니다.

- 번역본, 권 이름, 장·절 범위
- 카드에 실제 렌더링한 본문
- 배경 이미지와 글꼴·색상·정렬 설정
- 생성 시각과 원본 verse ID 목록

즉, 원문 데이터는 절 참조가 기준이고 게시 결과물만 불변 스냅샷을 가집니다.

## 모바일 오프라인 읽기

모바일은 `expo-sqlite`를 사용해 서버와 같은 권·장·절 구조를 기기에 저장합니다. TanStack Query는
화면 요청 캐시로 사용하고, 전체 성경의 영구 오프라인 원본 저장소로 사용하지 않습니다.

권장 흐름은 다음과 같습니다.

1. 앱에 검증된 초기 KOR1910 SQLite 스냅샷을 포함합니다.
2. 앱 시작 시 로컬 DB schema/content version을 확인합니다.
3. 네트워크가 있으면 서버 manifest의 version과 checksum을 비교합니다.
4. 변경된 번역본 또는 장만 임시 테이블에 내려받고 검증 후 원자적으로 교체합니다.
5. 네트워크가 없으면 모든 장 조회와 본문 검색을 SQLite에서 수행합니다.

북마크·하이라이트·스크랩은 로컬에서 먼저 반영합니다. 각 변경에 클라이언트 UUID와
`sync_status=PENDING`을 기록하고 온라인 복귀 시 서버로 전송합니다. 동일 항목 삭제와 수정이 충돌하면
`updated_at`과 삭제 tombstone을 기준으로 병합하며, 서버 반영 후 `SYNCED`로 변경합니다.

로그인 전 생성한 로컬 데이터는 익명 설치 ID에 연결하고, 로그인 후 사용자 동의를 받아 계정 데이터로
병합합니다. 성경 원문은 공개 데이터지만 개인 메모와 묵상 내용은 기기 보안 저장소 및 전송 구간 암호화
정책을 적용합니다.
