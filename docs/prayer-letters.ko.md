# 기도 편지 운영 계약

## 사용자 흐름

- 사용자는 성경 한 절을 대표 말씀으로 지정하고, 한국 시간 일요일에 시작하는 한 주의 기도제목을 작성·수정합니다. 일요일 작성 알림은 본인이 켠 경우에만 발송합니다.
- 기도제목은 기본 비공개입니다. 공개를 선택해도 수락한 친구만 볼 수 있습니다. 관계 해제·차단·비공개 변경 후에는 목록과 편지 전송이 막힙니다.
- 친구의 공개 기도제목에 주당 서로 다른 세 명까지 편지를 보냅니다. 같은 친구에게는 한 주에 한 통만 보낼 수 있습니다. 받는 사람에게 앱 내 알림과 등록 기기 푸시를 보냅니다.
- 네이티브 앱에서만 사용자가 선택한 보상형 광고를 볼 수 있습니다. 검증된 광고 한 건당 그 주의 발송 가능 인원이 한 명 늘며, 한국 시간 하루 최대 세 건입니다. 웹에는 AdMob 광고 버튼을 표시하지 않습니다.

## 서버 설정과 순서

1. 서버의 `V42.14__prayer_letters.sql`을 Flyway로 적용합니다. 기존 migration과 양 캐릭터 데이터 테이블은 수정·삭제하지 않습니다. 신규 앱이 공개되기 전에 새 API를 먼저 배포합니다.
2. Google AdMob에서 Android/iOS 보상형 광고 단위를 만든 뒤, 각 단위의 SSV callback URL을 `https://<API_DOMAIN>/api/v1/prayer/admob/ssv`로 지정합니다. Google 서명 키 조회를 위해 서버에서 `www.gstatic.com`으로 HTTPS 요청이 가능해야 합니다.
3. 서버 환경변수 `APP_PRAYER_ADS_ANDROID_UNIT_ID`, `APP_PRAYER_ADS_IOS_UNIT_ID`를 실제 광고 단위 ID로 설정합니다. 두 값과 앱의 AdMob App ID가 준비되고 콜백 검증을 확인한 뒤 `APP_PRAYER_ADS_ENABLED=true`로 켭니다. 기본값은 `false`입니다.
4. iOS/Android 앱 빌드에는 공개 식별자인 `EXPO_PUBLIC_ADMOB_IOS_APP_ID`, `EXPO_PUBLIC_ADMOB_ANDROID_APP_ID`를 넣습니다. 개발 빌드는 Google 테스트 App ID를 기본 사용하지만 운영 빌드는 실제 ID를 요구합니다. AdMob의 consent form 및 앱 개인정보 고지를 출시 전 점검합니다.

광고 표시 직전 앱이 UMP 동의 상태를 확인합니다. 시청 완료 이벤트만으로 보상하지 않고, Google 서명이 검증된 SSV 콜백의 거래 ID·광고 단위·요청 ID·시각을 확인한 뒤 DB 원장에 한 번 기록합니다. 콜백 지연 시 앱은 발송권을 재조회하며 중복 시청을 안내하지 않습니다.

## 데이터와 호환성

- 계정 탈퇴 시 기도 프로필, 친구 관계, 기도제목, 편지, 보상 요청, 알림을 외래키 순서로 삭제합니다.
- 기존 양 캐릭터 화면과 장착·발판·보상 코드 API는 유지합니다. 삭제 여부는 별도 작업에서 결정합니다.
- 장기 보존·자동 삭제 기간은 별도 개인정보 정책 결정 전까지 추가하지 않았습니다. 기도제목과 편지는 민감한 개인 서술이므로 공개 선택과 친구 권한을 서버가 매 요청마다 검사합니다.
