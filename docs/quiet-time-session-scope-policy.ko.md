# 고정 목장 및 일회성 QT 정책

## 목적

고정 목장은 장기간 유지되는 공동체이고 QT 세션은 특정 시점에 진행되는 활동입니다. 일회성 QT를 만들 때 새 목장을 자동 생성하지 않도록 두 수명주기를 분리합니다.

## 세션 범위

| 범위 | 목장 연결 | 관리자 | 기록 위치 |
| --- | --- | --- | --- |
| `PASTURE` | 필수 | 해당 목장 리더 | 고정 목장 활동 기록 |
| `STANDALONE` | 없음 | 세션 생성자 | 해당 일회성 세션 |

기존 데이터는 모두 `PASTURE` 범위로 마이그레이션합니다. 일회성 세션에는 `pasture_id`를 저장하지 않으며 생성 당시 사용자 ID와 표시 이름을 관리자 스냅샷으로 보관합니다.

## 생성과 관리 권한

- 고정 목장 QT는 해당 목장의 `leader_user_id`와 인증 사용자가 일치해야 생성할 수 있습니다.
- 일회성 QT는 로그인 사용자가 생성하고 해당 사용자만 QR 재발급, QR 폐기, 세션 종료를 수행할 수 있습니다.
- 다른 사용자는 QR 또는 초대 링크로 참여한 뒤 질문 답변과 묵상 기능을 사용할 수 있습니다.
- 일회성 세션 생성자의 답변 표시 이름은 생성 시점 JWT의 사용자 표시 이름을 사용합니다.

## 참여와 출석

- 두 범위 모두 QR 만료와 중복 참여 정책을 공통으로 적용합니다.
- 고정 목장 QT 출석은 `pasture_id`와 `session_id`를 함께 저장합니다.
- 일회성 QT 출석은 `pasture_id = null`로 저장하고 `session_id`로 모임을 식별합니다.
- 세션당 사용자 출석 유일 제약은 두 범위 모두 유지합니다.

## API 계약

```http
GET  /api/v1/quiet-time/pastures/mine
POST /api/v1/quiet-time/pastures/{pastureId}/sessions
POST /api/v1/quiet-time/sessions/standalone
```

세션 응답의 `pasture`는 `STANDALONE`일 때 `null`입니다. 클라이언트는 목장 존재 여부를 추측하지 않고 `scope`로 화면과 권한 문구를 결정해야 합니다.

## 후속 정책

- 고정 목장 멤버십과 리더·부리더 역할은 별도 membership 모델로 확장합니다.
- 일회성 QT 참가자를 고정 목장 멤버로 자동 전환하지 않습니다.
- 고정 목장 전환 시 새 목장을 만들고 참가자별 초대와 동의를 받아 membership을 생성합니다.
- 질문 답변이 생성된 이후의 질문 수정은 원문 변경 대신 질문 버전 또는 정정 기록으로 처리해야 합니다.
